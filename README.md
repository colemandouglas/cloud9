# Be Like Water

Training and recovery that adapts to you. People pick where they want to go, make the plan their own, and get an AI-built program that adjusts every 4 weeks based on how they're actually doing.

## What's in the beta

**Five starting goals** (on the home page):

1. General health and mobility
2. Train for an event: 5K, 10K, half marathon, marathon, HYROX, triathlons, Ironman, obstacle races, gran fondos, trail/ultra
3. Recover with your doctor's plan: upload MRI/X-ray reports, diagnosis, treatment plans (PDF or photos)
4. Lean out for an event or season: wedding, summer, ski season…
5. Get ready for an adventure: trek, high-altitude climb, ski trip, cycling tour…

**Then "make it yours":** schedule, equipment, likes/dislikes, what success looks like, start date.

**Safety first:** every journey has a general readiness screen (heart, chest pain, dizziness, pregnancy). A "yes" asks for a doctor's OK before the program is built. The medical path also screens for spine warning signs (cauda equina symptoms, progressive weakness, etc.). Any of those pause the journey, tell the person to see a doctor, and email the coach.

**The program:** Claude writes 4-week blocks (7 days a week, with exact exercises, sets/reps and coaching cues), a full-journey roadmap, stop rules, and general nutrition habits. It reads uploaded PDFs and images directly. At week 4 the person checks in, and the next block is rebuilt from their workout log (sessions done, effort, pain, notes).

**Daily use:** Today / Plan / Progress tabs, tick off exercises, log effort and pain, pain trend chart. Installable as an app from the phone browser.

**Coach view (`/coach`):** every journey, red flags and high pain first, intake, uploads, logs, a coach note the client sees and the AI follows, "cleared by a doctor" release, and rebuild. Pain of 7/10 or more on a medical journey emails the coach.

**Coming soon:** 1:1 coaching. There's a waitlist button in the app and the list shows in the coach view.

## Accounts

No passwords. People enter their email at the end of the builder and are signed in straight away. A confirmation link is also emailed for signing in on other devices. Returning emails always need the emailed link. Coaches are whoever is listed in `ADMIN_EMAILS`.

## Go live (beta)

You need four things:

1. **Hosting with a persistent disk.** `render.yaml` sets this up on Render (New → Blueprint → pick this repo). Starter plan with a 1 GB disk. Any host that runs the `Dockerfile` with a volume at `/data` works.
2. **Claude API key** from console.anthropic.com → `ANTHROPIC_API_KEY`. Expect roughly $0.50–$1.50 per 4-week block (Claude Opus 5.5 with high effort).
3. **Your email in `ADMIN_EMAILS`** so you get the coach view and alerts.
4. **Email (recommended):** a Resend API key (`RESEND_API_KEY`) and a verified sending domain (`EMAIL_FROM`). Without it, sign-in links and alerts are printed to the server log, which works for a private beta but not for anyone else.

Also set `APP_URL` to the public URL. `SESSION_SECRET` is generated by the blueprint.

**Private beta:** with `ADMIN_EMAILS` set to your email and `ALLOWED_EMAILS` left empty, anyone can sign up. To keep it to yourself (and anyone you invite), put invited emails in `ALLOWED_EMAILS`; coaches are always allowed. Set it to your own email for a solo test.

## Run locally

```bash
npm install
cp .env.example .env   # add ANTHROPIC_API_KEY, or AI_MODE=stub for placeholder programs
npm run dev            # http://localhost:5173
```

In dev, sign-in links show on screen and in the terminal.

## Stack

- React 19 + Vite + TypeScript (`src/`), PWA
- Express 5 on Node 22 with built-in SQLite (`server/`)
- Claude API via `@anthropic-ai/sdk`: structured JSON output, PDFs and images as input, server-side refusal fallback (`server/ai.js`)
- Shared goal catalog and screening questions: `shared/catalog.js`

## Before opening it beyond a private beta

- [ ] Clinical review of the AI coaching prompt (`server/ai.js`) and screening wording (`shared/catalog.js`) by a PT or physician
- [ ] HIPAA-eligible hosting with a BAA, encryption at rest, and backups (people upload medical records)
- [ ] Privacy policy and terms
- [ ] Rate limiting across server instances (the current sign-in throttle is in memory)
